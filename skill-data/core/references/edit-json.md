# edit.json

All times below are invented source seconds. encode.json is generated by init and never
edited. Change edit.json with commands (mode, cuts, speedups, chunks set, listen --try --apply);
they validate and save atomically, preserving key order and unknown fields. Only lessons and
review_flags are edited by hand, with a targeted change.
Older files without version load as-is; the first CLI save adds version 1.

```json
{
  "version": 1,
  "source": "/absolute/path/video.mp4",
  "mode": "step",
  "markers": ["Удалить"],
  "chunks": [
    {"id": 1, "start": 0.0, "end": 600.0, "status": "draft"},
    {"id": 2, "start": 600.0, "end": 900.0, "status": "draft"}
  ],
  "cuts": [{"from": 312.48, "to": 315.12, "reason": "фальстарт"}],
  "speedups": [{"from": 650.0, "to": 700.0, "speed": 8, "reason": "ожидание сборки"}],
  "review_flags": [{"at": 800.0, "note": "поворот головы: чистая склейка невозможна"}],
  "lessons": ["сохранять короткие паузы перед демонстрацией"]
}
```

- source is the joined source when init receives several recordings. Optional parts records
  each original path, its start in the joined source and its duration; it is informational.
- mode is step (review each chunk) or full (one review). init leaves it null until established.
- Chunks tile the source without gaps and end at its duration. Each status is draft,
  in_review or approved. Cuts and speed-ups cannot cross a chunk boundary.
- Cuts must have positive length, be within source, non-overlapping, and have a reason.
- Speed-ups require a whole-number speed >= 2, a reason, and cannot overlap cuts or each other.
  Their entire audio is muted; do not put needed speech in them.
- review_flags records deliberately unresolved decisions; lessons stores general preferences.
  Neither is a substitute for actual review or approval.

For shorts add `"keep": [{"from": 100, "to": 150, "reason": "selected topic"}]`.
Only those fragments remain. They must have positive lengths, stay within the source and not
overlap. Chunks tile each fragment, with gaps only between fragments. Internal cuts and
speed-ups must lie within a selected fragment. Everything outside keep is implicitly removed;
do not duplicate those gaps in cuts. Keep boundaries and chunk boundaries must agree.
